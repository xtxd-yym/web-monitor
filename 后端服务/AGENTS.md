# 云监控后端 AI 开发约束

- 技术栈：Node.js 22.12+、CommonJS、Express 4、mysql2、npm。保持现有 JavaScript 风格与接口兼容。
- 修改前阅读 package.json、package-lock.json、Dockerfile、配置和相关实现；禁止无关重构。
- 不新增或升级生产依赖，不换包管理器；完整锁文件纳入版本控制，CI 使用 npm ci。
- 禁止默认管理员密码、固定 JWT 签名密钥、硬编码或输出生产凭证；所有秘密来自环境变量/Secret。
- 管理接口必须验证 HttpOnly Cookie；公开 SDK 上报/配置和探针使用明确白名单。
- 禁止公开仓库源码、配置、SQL、数据库或日志目录；仅公开约定的 SDK 静态资源目录。
- 外部路径输入要校验；错误、AI 输出和客户文本进入 HTML 时必须转义，不信任原始 HTML。
- 生产 MySQL 由人工维护，应用不得自动建表、改表或迁移；SQL 文件仅为人工参考。
- 不在本地启动前后端、不安装运行依赖、不连接正式数据库、不调用真实 SMTP/Vanish 或正式 AI 服务。
- AI 自行完成必要静态检查和无外部副作用的 Mock 检查；不要给人工导入流程增加非门禁必需的测试或装依赖步骤。
- 客户数据、未脱敏日志、截图、Secret 和仅供本地展示材料不得提交；先确认远程存储适配性。
- 更新 README/DEPLOY 的完成边界和待部署事项，不能把本地验证写成已上线或生产验收通过。
- 历史导入和后续修复遵循任务号 290581、中文说明与如实的 AI 标识；测试和业务改动分开提交。
- 新修复使用当前真实时间，作者/提交时间一致、时区 +0800；不得改写旧历史或回填日期。
- 推送由用户在公司虚拟机执行；dev → feature MR 保留历史、不 squash，门禁通过后由非作者 reviewer 复核。
